# M4 R10 取证：自机 VM、子机、自机子弹与信仰保持矩形（2026-11-02）

一行结论：自机 VM（`P+0x14`）是嵌入对象，由 `FUN_004247f0` 以 `pl00.anm` 脚本 0 启动，每帧由 `FUN_00425730` 步进；左右立绘由 `FUN_004250b0` 按 x 步长符号直接用 `FUN_0043e710` 启动脚本 1–4，不用中断。子机与焦点判定图是世界 VM，分别在层 8 与层 13。子机回调 `+0x3330` 在自机更新循环中执行，绘制循环读的 `+0x3334` 没有写入者。自机子弹是 `P+0x49c` 起的 128 个 0x5c 记录，每颗持两个世界 VM 句柄，在层 8 绘制，命中时由 SHT 的命中脚本生成火花。信仰保持矩形是两个高 2 px 的 `FUN_0043bda0` 矩形，宽度随计时器增长，原作绘制，Go 不绘制。

依据 th10.exe v1.00a 反编译与汇编（`tools/ghidra/dump.py`，项目 `%LOCALAPPDATA%/th10-ghidra-render`），以及仓库内嵌的 `pl00.anm`、`bullet.anm`、`sht/pl00a.sht` 等（经仓库 `th10/anm`、`th10/sht` 解析的临时程序，`.tmp/r10/`）。新增 dump 在 `.tmp/ecl_dump/r10/`（清单见末尾）。前置文档：`m4_r8.md`（R8-B）、`m4_r9.md`（格式，以及 `FUN_0043e710`、`FUN_00449350`、`FUN_004492f0` 的约定）、`m4_r6.md`（VM 布局与 TFACTOR 读法）。

约定：地址为 th10.exe 虚拟地址。`P` 为自机对象（`DAT_00477834`）。`VM+0xNN` 指 ANM VM 基址偏移（字段名见 `anm/vm.go`）；自机的嵌入 VM 基址为 `P+0x14`，因此 `VM+0xNN` = `P+0x14+0xNN`。子机槽 `O_k = P+0x32a0+0x98·k`（k = 0…3），`O+0xNN` 指 `O_k` 的偏移。自机射击记录 `R_k = P+0x49c+0x5c·k`（k = 0…127）。坐标与速度的整数单位为 1/100 px。调用约定（寄存器传参与 `RET n` 的参数清理）以逐条汇编为准。标注 **（推测）** 的是未逐条核实的内容。无法确定的事项列在最后一节。

### A.2 左右切换（Q2）

**触发与输入。** `FUN_00425730` 在状态 1 中于 `0x425a8c` 调 `FUN_004250b0`（每帧）。方向码 `P+0x454` 由 `DAT_00474e5c` 的键位决定（`r10/func_4250b0.asm` 的分支，`0x4250b3`–`0x42512x`）：`0x10` 上、`0x20` 下、`0x40` 左、`0x80` 右，组合为斜向；`0x04` 为焦点键（`0x425180`–`0x425188`，同时要求 `[P+0x48c] ≥ 4` 且敌机管理器 `[M+0x60] ≠ 0`，否则焦点为 0，`0x425172`–`0x425177`）。

**步长。** 由方向码选出 x 步长（`EBP`，单位 1/100 px/帧）：直行 `±[P+0x3d4]`（非焦点）或 `±[P+0x3d8]`（焦点），斜行 `±[P+0x3dc]` 或 `±[P+0x3e0]`。数值来自 SHT 头部（`sht.ParseMovement`，`pl00a/b/c` 相同）：直行 450 与 200（4.50、2.00 px/帧），斜行 318 与 141。

**切换条件。** 新 x 步长 `EBP` 与上一帧的 `[P+0x44c]`（`0x4253f8` 写回）比较，只用符号与零比较，没有数值阈值：

| 条件 | 调用 | 脚本（`EBX`） | 地址 | pl00.anm 中的内容（扫描） |
|---|---|---|---|---|
| x < 0 且原 x ≥ 0 | `FUN_0043e710`（`EAX = P+0x14`，`ECX = P+0x10`） | 1 | `0x425385`–`0x425390` | sprite 8–15，`t0`–`t19` 加速，之后 op4 循环 |
| x > 0 且原 x ≤ 0 | 同上 | 3 | `0x4253a7`–`0x4253eb` | sprite 16–23，`t0`–`t19`，之后 op4 循环 |
| x = 0 且原 x < 0 | 同上 | 2 | `0x4253bc`–`0x4253c7` | sprite 11→8，再 0–7 循环 |
| x = 0 且原 x > 0 | 同上 | 4 | `0x4253e0`–`0x4253eb` | sprite 19→16，再 0–7 循环 |

其他情况不调用。`pl00.anm` 脚本 0（静止）为 sprite 0–7，每个 5 帧（`t0`、`t5`…`t35`），`t40` 为 op4 回到起点；脚本 0 的 op4 参数为 `(0, 0)`（回到起点）；脚本 1、2、4 为 `(0x30, 3)`；脚本 3 为 `(0x3c, 4)`（`anm/vm.go:547` 的 `vm.jump(arg0, arg1)`；`anm/loader.go` 注释称 ins_4 为循环）。

**不是中断，也不是 `FUN_0043e8b0`。** `FUN_0043e710`（`r6/func_43e710.asm`）是“按脚本号启动”：`EAX` 为 VM，`ECX` 为文件，`EBX` 为脚本号；它检查文件的脚本表 `[file+0x11c][EBX]` 与加载标志 `[file+0x124]`，清 VM（`FUN_00401de0`，保留 Offset 与 Layer），写 `VM+0x308 = file`、`VM+0x38a = EBX`、清 `VM+0x35c` 的 bit 0 与 `0x600`，最后 `FUN_0043ee30`（首帧）。`FUN_004250b0` 中没有对 `FUN_00449470` 或 `FUN_0043e8b0` 的调用。

**Go 对照。** `entity/player/player.go:577`–`613` 的 `updateAnim` 用 `KeyLeft`、`KeyRight` 的按键状态，`frontFrameTime = 8`、`transFrameTime = 6`，转身过渡 3 帧后进入侧身。与原作的脚本时间表不同（见 Go 对照表）。

### A.4 无敌闪烁（Q4）

**时间器。** `Invinc` 为 `P+0x430c`（zun.Timer：`Prev` 在 `+0x00`，`Cur` 在 `+0x04`（即 `P+0x4310`），`F` 在 `+0x08`，gs 指针在 `+0x0c`；构造 `0x424d14`–`0x424d28` 设 Prev = 119、Cur = 120）。状态计时器 `StateTimer` 为 `P+0x474`（Prev）、`P+0x478`（Cur）、`P+0x47c`（F）、`P+0x480`（gs）。

**每帧写入（`FUN_00425730`）。**

| 地址 | 指令（摘要） | 作用 |
|---|---|---|
| `0x425e46`–`0x425e50` | `EAX = [P+0x4310]`；`JLE 0x425ee6` | `Invinc.Cur ≤ 0` 时不闪，只清 `0x8000` |
| `0x425ea4`–`0x425eaf` | `Invinc.Cur` 更新 | 计时器推进（与闪烁无关） |
| `0x425eb5`–`0x425ebb` | `CMP [P+0x478], [P+0x474]`；`JZ 0x425ee6` | `StateTimer.Cur == Prev` 时不闪 |
| `0x425ec3`–`0x425ecd` | `CDQ; IDIV 3; TEST EDX, EDX; JNZ 0x425ee6` | `Cur % 3 ≠ 0` 时不闪 |
| `0x425ecf`–`0x425edf` | `MOV [P+0x314], 0xff0000ff`；`OR [P+0x370], 0x8000` | 闪烁帧：颜色 2 与颜色选择位 |
| `0x425ee6`–`0x425eec` | `AND [P+0x370], 0xffff7fff` | 非闪烁帧：只清颜色选择位，颜色 2 不复位 |
| `0x425efb` | `CALL FUN_0043ee30`（`P+0x14`） | VM 步进（之后绘制） |

结论：每 3 帧亮 1 帧（`Cur % 3 == 0`），亮的那一帧写颜色 2 `0xff0000ff`（ARGB：蓝色，alpha 255）并置 `0x8000`，颜色 2 作为 TFACTOR（`m4_r6` 的 `flags & 0x8000` 读法）。周期与门控以 `StateTimer` 为准，不以 `Invinc` 为准。

**Go 对照。** `entity/player/player.go:314`–`317`：`p.Flash = p.StateTimer.Cur != p.StateTimer.Prev && p.StateTimer.Cur%3 == 0`，门控 `p.Invinc.Cur >= 1`。门控、时间器、周期一致。差异：

- 颜色：原作是 VM 的颜色 2 蓝色 TFACTOR；Go 在 `scene/stage/stage.go` 的 `drawPlayer` 中用 `alpha = 0.3` 的半透明代替（注释已说明）。

### B.1 `+0x3330` 与 `+0x3334` 的不一致（Q1，解决 m4_r8 无法确定 #2）

**写入者（`FUN_00426f70`）。** 函数的 EBP 为 `P`（`0x426f89`）。子机循环的寄存器为：`ESI = k`（`0x427187`，`0…3`），`EAX = 0x98·k`（`0x4271a8`），`EDI = EAX + EBP = P + 0x98·k`（`LEA EDI,[EAX+EBP*1]`，`0x4271ae`）。因此在这个函数中 `EDI` 不是 `O_k`，而是 `P+0x98k`：子机字段的地址为 `EDI + 0x32a0`（状态，`0x42783a` `MOV [EDI+0x32a0],2`）、`EDI + 0x3308`（句柄，`0x427352` `MOV [EDI+0x3308],EAX`）、`EDI + 0x3330`（回调，`0x427372` 与 `0x4275d9`）。`EDI` 既不是槽基址，也不是槽基址 + 4，而是 `O_k − 0x32a0`。

- 写入的回调：`P+0x3330+0x98k = O_k+0x90`。
- `--writes 0x3330`（`_writes.txt`）：只有 `FUN_00426f70` 的两个写入（`0x427372` → `0x427ad0`，`0x4275d9` → `0x427950`）。

**读取者（绘制循环，`FUN_00426360`）。** `LEA ESI,[EDI+0x3334]`（`0x4263b3`，`EDI = P`），`MOV EAX,[ESI]`（`0x4263c0`），`LEA ECX,[ESI-0x94]`（`0x4263c6`，`ECX = O_k`），`CALL EAX`（`0x4263cc`），`ADD ESI,0x98`（`0x4263ce`）。即读取 `O_k+0x94`。

**无写入者。** `--writes 0x3334`（`_writes.txt`，`== stores to +0x3334 ==` 后为空）：没有任何 `[reg+0x3334]` 的写入。因此绘制循环的 4 次检查（`0x4263c0`–`0x4263d5`）读到的都是 0，什么也不调用。**（推测）** 未能排除经指针的间接写入（例如 `[ESI+4]` 形式），但直接位移形式没有写入者。

**有效回调（`FUN_004250b0`）。** 每帧，状态 1 中：`EBX = P+0x32e0+0x98k`（`0x4255b9`，`0x4255c7`），`LEA ECX,[EBX-0x40]`（`0x4255cc`，`ECX = O_k`），`MOV EAX,[EBX+0x50]`（`0x425600`，即 `P+0x3330+0x98k`），`TEST EAX`（`0x425603`），`CALL EAX`（`0x425607`）。
