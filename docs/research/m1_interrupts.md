# M1：Boss 阶段中断与 ECL 执行模型（2026-10-27）

依据：Ghidra 12.2 无头导出（`tools/ghidra/dump.py`，输出在 `.tmp/ecl_dump/round3/`），
`th10.exe` v1.00a。实现：`scene/stage/ecl/interrupt.go`、`vm.go`、`game_ops.go`。

## 敌机结构（基址 B，相对敌机对象）

| 偏移 | 含义 |
|---|---|
| B+0x23fc | 当前 HP |
| B+0x2494 + 0x10·i | 中断槽 i（0–7）：`{hp, time, sub, timeoutSub}`，hp < 0 表示未启用 |
| B+0x1158 | 阶段计时器（333 重置），`{int cur; float f}` |
| B+0x508 | 无敌计时（335 设置，帧末递减） |

全局：Boss 槽 `DAT_00477704+0x10`（8 个，332 写入）；HUD 计时 `DAT_0047770c+0x9ec0`；
信仰 `DAT_00474c4c`。

敌机标志（322/323）：0x1/0x10 不查询伤害；0x2 无体判定；0x4 出屏不删；0x8 不扣 HP；
0x40 HP 为 0 不死；0x100 已进入画面；0x2000 本帧被击中；0x8000 是 Boss；0x10000 超时。

## FUN_004127a0（中断检查）

1. **HP 路径**：取第一个已启用（hp ≥ 0）的槽；若当前 HP ≤ 槽 hp，HP 置为槽 hp，
   清除该槽，重置阶段计时器，清 0x10000，返回 `sub`；HP 大于槽值则停止查找。
2. **时间路径**：取第一个 time ≥ 1 的已启用槽，HUD 计时 = `min(99, (time − cur + 59) / 60)`；
   cur < time 时返回"无"；否则 HP 置为槽 hp，清除该槽，重置计时器，置 0x10000，
   信仰 −3000（下限 5000；本项目信仰按 ×10 存储，即 −30000、下限 50000），返回 `timeoutSub`。

334 写入 `sub = timeoutSub = 参数 3`；341 只覆写 `timeoutSub`（道中 Boss 用于"逃跑"）。

## FUN_0040dc80（敌机每帧更新）中与中断相关的部分

- 检查 1：伤害结算之后执行；命中则**当帧**执行新子程序。
- 检查 2：无条件执行；命中的新子程序从**下一帧**开始执行。
- 中断：释放该敌机全部异步任务，主任务 IP 与时钟归零，**保留调用栈**。
- 随后递减无敌计时，推进阶段计时器（timeScale 在 0.99–1.01 内时按整数 +1，否则按浮点累加）。

## FUN_0044e1a0（任务执行器）

- `wait(n)` 实现为时钟减 n，因此 wait(1) 之后的指令恰好在下一帧执行。
- 游戏指令返回 -1 表示阻塞：下一帧从同一条指令重试，时钟不前进（339、340 均如此）。
- op 1，以及调用栈为空时的 op 10，结束任务：主任务结束会删除敌机，异步任务只释放自身。

## FUN_00450470（按名查找子程序）

stage ECL 与 ECLI 列表中的文件（`default.ecl`）合并成一张有序表。找不到子程序时，
敌机在下一次执行时被删除。各关 ECL 均未重定义 `default.ecl` 的子程序（`TestStageVMIncludesDefaultECL`）。

## 已验证的行为

- 二面 Hina：受到 6400 伤害后 HP 被钳到 2700，当帧进入 BossCard1，异步任务清空，
  `Ecl_EtBreak` 消弹敌机（无 ANM、不可射击、不绘制）生成；HUD 显示 45 秒。
- 超时：第 2700 帧置 0x10000，主子程序换成 Boss2，HP 被置为槽值 0，信仰 −3000；
  死亡判定只在受伤时进行，而下一帧 Boss2 的 331 先于伤害执行，把 HP 设为 13400。
- BossDead 置 0x40 后 HP 打空不删除，60 帧后自行删除并清 Boss 槽。
- 不射击时 1–3 面全程超时通关（`TestVMBossesTimeOutToClear`）；4–6 面的 main 是死循环，
  原作由通关对话的 MSG op 20 结束关卡（M5）。

## 推迟到 M2 的差异（已知、未建模）

1. **更新交错**：原作逐个敌机执行"移动→ECL→伤害→检查 2→计时"；本项目先执行全部 ECL，
   再统一结算碰撞，最后 `LateUpdate` 做检查 2 与计时。对同一帧内敌机之间的相互影响
   （如 Boss 死亡与 340 的等待者）可能相差一帧。
2. **创建帧的双重更新**：创建指令当场执行新敌机一次；之后同一帧的主循环是否再更新它，
   取决于链表插入位置，尚未核对。
3. **异步任务顺序**：原作新任务插在链表头（新的先执行），本项目按创建顺序执行。
4. **伤害 /5 规则**与 HP 变化音效（FUN_0040dc80 中的分支）未移植。
5. **浮点阶段计时器**：只在 timeScale ≠ 1 时有区别，已按原作实现，但未经差分验证。
6. **体判定计时 B+0x1430**、得分与掉落（`FUN_00409d90`、`FUN_0040e5f0`）未移植。
7. **超时时清除自机标志**（`FUN_004127a0` 时间路径中的附带写入）未移植。
8. **道中 Boss 超时 HP=0**：超时后 HP 为槽值 0，逃跑子程序不重设 HP，此时再被击中即满足
   "HP < 1 且无 0x40"而死亡。按代码推断原作如此，本项目照此实现，但未经回放验证。
9. **同步调用未知子程序**：原作行为未核对，本项目忽略该调用。
