### A.3 回答 1–5

**1. UV 的分母与半像素。** UV 的公式是

- `u0 = (S.x · f1) / Wd`，`u1 = ((S.w + S.x) · f1) / Wd`，`v0 = (S.y · f2) / Hd`，`v1 = ((S.h + S.y) · f2) / Hd`，其中 `f1 = Wd / We`，`f2 = Hd / He`。

代入后分子分母的 `Wd` 相消，数学上等于 `S.x / We`，即条目头的 w/h。也就是说 UV 实际上以条目头尺寸为分母。若 D3DX 因非 2 的幂而把纹理补齐到 2 的幂，`Wd ≠ We`，两者仍相消。float32 的舍入顺序仍按上式（`0x447621–0x44767f`）。

没有半像素偏移，也没有 epsilon：`FUN_00447470` 与 `FUN_00447940` 的常量只有 `0x470b98`（2^32，用于 `FILD` 的无符号修正）。

**2. 纹理创建。**

- 外部图像（`entry+0x34 == 0`）：`FUN_00446eb0` 调用 `D3DXCreateTextureFromFileInMemoryEx`（`render/func_446eb0.c` 的参数表）：
  - `pDevice = DAT_00491c30`，`pSrcData = item+4`，`SrcDataSize = item+8`；
  - `Width = entry+0xc`，`Height = entry+0x10`（来自 `FUN_00447470` 压栈，`0x4474ec–0x44750e`）；
  - `MipLevels = 0`，`Usage = 0`，`Format = DAT_0046f288[entry+0x14]`（`EAX = [EBP+0x14]`，`0x44750a`）；
  - `Pool = 1`（D3DPOOL_MANAGED），`Filter = 1`（D3DX_FILTER_NONE），`MipFilter = 0xFFFFFFFF`（D3DX_DEFAULT）；
  - `ColorKey = entry+0x18`；`pSrcInfo = 0`，`pPalette = 0`，`ppTexture = item+0`。
  - 之后 `item+0xc = DAT_0046f2a0[format]`（`func_446eb0.c`）。
  - 在 16 位显示模式（`DAT_00491d78 & 1`）下，格式 21 或 0 改为表项 5，格式 20 改为表项 3（`func_446eb0.c` 开头）。
- 内嵌图像（`entry+0x34 != 0`，即 THTX）：`FUN_00446f40`（`func_446f40.c`）：
  - `D3DXCreateTexture(W, H, 1, 0, DAT_0046f288[entry+0x14], 1, item)`；
  - `GetSurfaceLevel(0)`（vtbl 0x48）；
  - `D3DXLoadSurfaceFromMemory(surf, 0, rect, src = THTX+0x10, DAT_0046f288[THTX.format], pitch = THTX.w · DAT_0046f2a0[THTX.format], filter = 1, colorkey = 0)`；
  - `item+0xc = DAT_0046f2a0[entry+0x14]`。
  - THTX 头（`thtypes/anm_types.h`）：`magic[4]`、`zero`（+4）、`format`（+6）、`w`（+8）、`h`（+0xa）、`size`（+0xc）、数据从 +0x10 开始；与代码一致。
- 格式表 `DAT_0046f288`（`_data_tables.txt`）：索引 0→0（UNKNOWN），1→21（A8R8G8B8），2→25（A1R5G5B5），3→23（R5G6B5），4→20（R8G8B8），5→26（A4R4G4B4），6→4，7→4。其中 4 不是合法的 D3DFORMAT 值。`DAT_0046f2a0`（每像素字节数）为 4、4、2、2、3、2，之后两项 97、119 显然不是有效值。
- **Gray8（THTX 格式 7）**：没有找到展开代码。格式表中 7 对应无效值 4，D3DX 会失败，`FUN_00446f40` 或 `FUN_00446eb0` 返回非零后调用错误输出（`0x44751b`、`0x447562`，错误串 `DAT_004701b0`、`DAT_0047016c`）。（推测）TH10 数据里不含格式 6、7，或它们走了别的路径；未核实。

**3. `@` 条目。** `FUN_00447470` 在 `0x4474c5–0x4474e7` 中调用 `FUN_00447050(h, w)`（`render/func_447050.c`）：`D3DXCreateTexture(DAT_00491c30, Width = entry+0xc, Height = entry+0x10, 1, 0, DAT_0046f288[format], 1, item)`，然后 `item+0xc = DAT_0046f2a0[format]`。这是一张空白的 managed 普通纹理，没有 `D3DUSAGE_RENDERTARGET`，也不上传像素。`FUN_004472e0` 对 `@` 名字不读文件。没有找到往这张纹理写入像素的代码。（推测）它是运行时由游戏代码填充的纹理，填充者未追踪。

**4. 同名条目。** 不共享。`FUN_004472e0` 对每个条目单独调用 `FUN_0044b360(name, 1)` 读磁盘，`FUN_00446eb0` 为每个条目单独创建 D3D 纹理。`FUN_004470c0`、`FUN_004472e0`、`FUN_00447470` 中都没有按名字查找已加载纹理的逻辑。`thtk` 的 `next_by_name` 字段只在其工具中使用。

**5. 精灵指令与 VM+0x4c/+0x50。** `FUN_0043e5a0`（`func_43e5a0.asm`）：
- `0x43e5d8`：`VM+0x394 = file+0x118 + idx·0x44`；
- `0x43e5de–0x43e5e1`：`VM+0x4c = rec+0x34`（宽）；
- `0x43e5ea–0x43e5ed`：`VM+0x50 = rec+0x30`（高）；

- `VM+0x23c = VM+0x4c · (1/256)`（`0x43e6b4–0x43e6bd`，`DAT_00470b7c = 2^-8`）；
- `VM+0x250 = VM+0x50 · (1/256)`；
- `VM+0x2bc = (rec+0x38 / rec+0x1c) · VM+0x4c`（`0x43e6d4–0x43e6dd`）；
