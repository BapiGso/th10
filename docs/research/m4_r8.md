# M4 R8 取证：绘制链节点 0x14、0x16、0x19、0x1b、0x1d 的绘制内容与 #14 未决项（2026-11-01）

一行结论：原作 0x14 是空桩；0x16 只画自机 VM 与两次外框，子机与子弹不在此节点；0x19、0x1b、0x1d 在绘制遍历里先写 VM 位置再画（Go 在 calc 阶段写同样的字段，时机不同）；#14 的符卡块绘制（`DAT_004776f4`）在原作的 0xe、0x25 节点，Go 未画。

依据 th10.exe v1.00a 反编译与汇编（`tools/ghidra/dump.py`，项目 `%LOCALAPPDATA%/th10-ghidra-render`）。新增 dump 在 `.tmp/ecl_dump/r8/`（清单见末尾）。前置文档：`m4_r6.md`（R6-F、附加 2、无法确定 #14）、`m4_render_re.md` §1.3、`m4_render.md` §2.2、`m4_r7.md`（R7-E、R7-F）。

约定：地址为 th10.exe 虚拟地址。`VM+0xNN` 指 ANM VM 基址的偏移（字段名见 `anm/vm.go`）。`P` 为自机对象（`DAT_00477834`，`m2_motion.md` 第 34 行），`M` 为各管理器。标注 **（推测）** 的是未逐条核实的内容。无法确定的事项列在最后一节。

### A.2 绘制内容

- 调用路径：无。回调不调用 `FUN_004451c0`、`FUN_00448980`、`FUN_00442670`，也没有设备调用。

### A.3 敌人 VM 实际的绘制路径（间接证据）

- 所有 ANM VM 由层表绘制。`FUN_00448980`（`render4/func_448980.asm`，`0x448980–0x4489c2`）遍历 `[M + L·0x3ac + 0x72db00]`（层 L 的链表头），沿 `VM+0x1c` 前进。对 `VM+0x35c & 0x4000000 == 0` 的 VM，先调 `VM+0x39c`（若非零），再 `CALL 0x4451c0`（`EAX = VM`，`ECX = M`）。
- 层表由 `FUN_00448860`（`render4/func_448860.c`）在 calc 阶段重建：遍历活动表 `[M+0x72dad4]`，非隐藏 VM 先调 `VM+0x398`，再 `FUN_0043ee30`（ANM 步进）。存活的 VM 按 `VM+0x20` 挂入对应层的尾部。
- 因此敌人 VM 若存在，应在层节点（0x9、0xb、0xd、0xf、0x10–0x13、0x15、0x17、0x18、0x1a、0x1c、0x21、0x24、0x29、0x2a）中的某一个画出。哪一层，取决于敌人 VM 的 `+0x20`，未确定。
- 敌人 VM 的创建函数未追踪。`FUN_00409280`（把 VM 挂入活动表 `0x72dad4/0x72dad8`）的唯一调用者是 `FUN_0040e770` 的 `0x410f3a`（`r8/_callers.txt`），传入的所有者是符卡块 `DAT_004776f4`，因此它是符卡 VM 的路径（见 R8-F），不能作为敌人 VM 的来源证据。

### B.3 子机回调（4 个槽）

- 槽基址 `O_k = P+0x32a0 + 0x98k`（k = 0..3）。`FUN_00426f70`（`r8/func_426f70.asm`）用 `+0x32a0` 作状态字（`0x42783a` `MOV [EDI+0x32a0],2`），用 `+0x3308` 存子机 VM 的句柄（`0x427352` `MOV [EDI+0x3308],EAX`），并写回调地址 `0x427ad0`（`0x427372` `MOV [EDI+0x3330],0x427ad0`）与 `0x427950`（`0x4275d9`）。
- **偏移不一致**：绘制循环读 `[P+0x3334+0x98k]`（`0x4263b3`–`0x4263cc`），而 `FUN_00426f70` 写 `[P+0x3330+0x98k]`（反编译显示 `EDI` 为槽基址，**推测**）。两者相差 4 字节，本轮未找到 `+0x3334` 的写入者（无法确定 #2）。
- 若按写入者的偏移解释，回调为：
  - `0x427ad0`（`MOV EDI,ECX; CALL 0x427ae0`，`r8/func_427ad0.asm`）→ `0x427ae0`（`r8/func_427ae0.asm`）。不调用 `FUN_004451c0`。它检查 `[EDI+0x84]`，并在 `[DAT_00477834+0x4474]` 决定的分支中调用 `FUN_00449470`（`0x427af5–0x427b03` 与 `0x427b1d–0x427b29`；`ESI = 6` 或 `3`，`EAX = O+0x68`）。`FUN_00449470` 通过 `FUN_004491c0` 找到 VM，把 `SI` 写入 `VM+0x304`（`r8/func_449470.asm`；`anm/vm.go:157` 的 `pending int16`，即待执行的中断标签）。之后复制 `O+0x3c/0x40` 到 `O+0x4c/0x50`，并写 `O+0x34/0x38`（`0x427b08–0x427b3a`）。
  - `0x427950`（`CALL 0x427960`，`r8/func_427960.asm`，94 行）。`0x427960` 未逐条核对；它含对 `FUN_00463b2c`（`_ftol`）的调用。
- 子机 VM 的句柄在 `O+0x68`。`FUN_00426f70` 在活动表 `0x72dad4/0x72dadc` 中查找该句柄（`death2/func_426f70.c` 行 39–57、131–135，即比较 `*piVar == 句柄`）。因此子机 VM 应经层表（`FUN_00448980`）绘制，不经本节点（**推测**，层号未确定）。

### B.4 自机 VM 与矩形的 flush、缓存

- `0x4263ae` 的 `CALL 0x4451c0` 前后没有 `FUN_00442f50`。
- `FUN_0043bda0` 入口调用 `FUN_00442f50`（`0x43bdaa`）。绘制后它把缓存设为：纹理 0（`0x43bf1d`）、顶点类型 0xff（`0x43bf11`）、精灵指针 0（`0x43bf17`）、混合模式 3（`0x43bf29`）、`+0x3ada6b` = 0xff（`0x43bf30`）。这些写入与 `m4_render_re.md` §3.1 的缓存表一致。

### B.5 `FUN_0043bda0`：非 ANM 的顶点绘制（矩形）

- 设备为 `[0x491c30]`，虚表索引按 D3D9 的 `IDirect3DDevice9` 布局核对：`+0xe4` = SetRenderState（索引 57）、`+0x10c` = SetTextureStageState（67）、`+0x14c` = DrawPrimitiveUP（83）、`+0x164` = SetFVF（89）。
- 调用顺序：
  1. `FUN_00442f50`（flush，`0x43bdaa`）。
  2. `SetRenderState(20 = D3DRS_DESTBLEND, 6 = D3DBLEND_INVSRCALPHA)`（`0x43bed2`–`0x43bed7`）。源混合未在本函数设置（沿用调用前的状态）。
  3. `SetFVF(0x44 = XYZRHW | DIFFUSE)`（`0x43bee4`–`0x43bee7`）。
  4. `DrawPrimitiveUP(5 = D3DPT_TRIANGLESTRIP, 2, 栈上 4 个顶点, 0x14)`（`0x43befb`–`0x43bf00`）。顶点由 `EDI` 指向的 4 个 float 构造。
  5. 缓存写入（`0x43bf06`–`0x43bf30`，见 B.4），再若干次 `+0x10c` 调用。
- 结论：这是一个无纹理、顶点颜色来自调用方的矩形绘制（自机调用时颜色取 `EBX`），不经过 ANM VM。
