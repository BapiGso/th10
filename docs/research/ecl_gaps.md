# ECL 运动与弹幕：与原作的偏差审计（2026-10-26）

对照依据：`.tmp/ecl_dump/`（th10.exe v1.00a 的 Ghidra 反编译）。主文件 `round2/func_40e770.c`
（运动约 :414-765，320–368 约 :766-1186，弹幕约 :1190-1774）。下文"dump"指该目录。

结论：所有关卡都在跑原版 ECL 字节码（stage1 `NewStage01VM`，stage2-6 `NewStageVM`，Extra 跑
`stage07.ecl`），轨迹对不上来自 VM 语义的**系统性偏差**，不是个别指令的笔误。

## 1. 位置取整（影响最大）

原作每帧把各运动层位置和最终 A+B 之和取整到 0.01：`x = floor(x*100)*0.01f`
（`FUN_0044c2a0`，`round2/func_44c2a0.c`；由敌人更新 `top/func_0040dc80.c` 调用；`FUN_00452ff0`
为取整辅助，尚未 dump）。项目 `integrate`（`scene/stage/ecl/game_ops.go:76-104`）从不取整，长路径上
位置会逐渐偏离。

## 2. 缓动

| | 原作 | 项目 |
|---|---|---|
| 位置缓动 | `FUN_00404610`（未移植） | `easeFrac`（`game_ops.go:841-861`）：1=f²，2/4=1-(1-f)²，3=smoothstep，其余线性 |
| 速度/圆周缓动 | `FUN_00412ac0` | 同上 |
| mode 7 | 每帧加 delta，持续 `time` 帧（实际落地 time-1 次）后停止 | 永久加速度/角速度，忽略帧数 |
| mode 8 | 零切线三次 Hermite = smoothstep | **线性** |
| mode 17 (0x11) | value += vel; vel += accel | 无 |
| 其余模式 | 经 `FUN_0044c350(time,total)` 查表 | 无法核对——**该函数未 dump** |

除 mode 7 外，原作在运动结束时精确落在目标值上。

## 3. 运动语义

| 指令 | 原作 | 项目 |

| 281/283 movePosTime | 从当前位置出发；未设置参数保持当前值；不做 flip；不动速度运动 | 在 flip 下镜像目标（`tx = 2*l.x - tx`），并清空速度运动（`game_ops.go:440-466`） |
| 285/287 moveVelTime | mode 7 未设置参数取 0；其余保持当前值，flip 镜像角度；角度走短路径（差 ≥π 时给较小者 +2π，mode 7 也一样）；不取消位置运动 | 清空位置运动 |
| 288/290 moveCircle | 真正的绕圆：未在绕圆时圆心=当前位置；每帧 angle+=angVel、radius+=radiusVel、pos=圆心+polar(angle,radius) | 只旋转航向（`opMoveCircle`，`game_ops.go:478-498`） |
| 289 / 291 | `SSffff` 缓动绕圆 | 289 不在格式表；291 格式写成 `SSfffS`；均未实现 |
| 294 | layer A 位置 = 0 号 Boss 槽位置 | "moveStop"，清零 layer A（`game_ops.go:214-219`） |
| 295 | layer B 位置 = Boss 位置 | 忽略 |
| 296 | layer A 加 (x,y,z)，3 个 float，不做 flip | moveAdd，格式 `SSf`，flip 下镜像 dx（`game_ops.go:201-211`） |
| 297 | layer B 加 (x,y,z) | 忽略，格式 `ff` |
| 298 / 299 | 设置 layer A/B 的圆心（或速度），然后该层 = Boss 位置 | 298 当作 moveAdd B；299 设置 layer B 航向/速度（`game_ops.go:220-233`） |

- **两层同时运行**：原作位置运动与速度运动并行；项目 `step`（`game_ops.go:106-145`）在位置运动
  进行中直接 `continue` 跳过速度运动。
- **flip**：原作只镜像 284–287 显式设置的角度（a → π−a）。项目在积分时 `dx = -dx`，连随机移动、
  mode 7 旋转、281/283 目标、296 偏移都被镜像——带角速度的镜像敌人会转错方向。
- **layer B 全局偏移**：原作在标志 0x40000 时给 layer B 加全局偏移；项目没有。
- **"未设置"哨兵**：原作为 double -999999.0（`DAT_00470d58`，v <= -999999 视为未设置）；
  `consts.txt` 误读为 0.0。项目 `eclUnset` 为 `v <= -900000`（`game_ops.go:895`），对现有数据可用。
- **moveLimit 324/325**（`game_ops.go:234-248`）与原作一致（标志 0x200，half=w*0.5，修正写回 layer A）。
- **moveRand 292/293**（`game_ops.go:543-582`）逻辑同原作 case 0x124，但用 float64 π 常量；
  原作用 float32 π/2、π/3。

## 4. 坐标与精度

- `eclToWorld` = (224+x, 16+y)（`vm.go:855`），与原作边界一致。
- 原作 float32 存储 + x87 中间值；项目全程 float64（`moveLayer`，`game_ops.go:40-49`）。
  需先确认 `CreateDevice` 是否带 `D3DCREATE_FPU_PRESERVE`：不带则 x87 精度控制为 24 位，
  Go float32 运算即可逐位对齐。
- `normAngle`（`vm.go:842-851`）为 float64、无迭代上限；原作用 float32 π，上限 0x21 次。
- `aimAngleAt`（`vm.go:809`）两点重合返回 π/2，与 `FUN_004073e0` 一致。
- 震屏 `ShakeOffset`（`vm.go:234`）图案是自创的（原作 `FUN_0043c8b0`，未 dump）。

## 5. RNG

- 生成器与原作 `FUN_0044bb90`（`helpers/func_44bb90.c`）位精确：`rngRaw`（`vm.go:819-826`），
  `randSigned`/`randFloat`（`vm.go:832/838`）缩放常量与 exe 一致。
- **种子写死** `rngState: 0x1234`（`vm.go:146`）；原作取回放章节头 +0x02。
- **原作 ANM 引擎共用同一 RNG 状态**（`FUN_0043ee30` case 0x28/0x29、`FUN_0043eac0`），每次动画
  抽随机数都会推进序列。项目未建模，即使种子对了也会漂移。
- special 变量（`specialFloat`，`vm.go:781-798`）只处理 6 个：-9959 难度，-9986→0，-9989 自机角，
  -9987/-9999 随机 float，-9998 随机角，-10000 帧计数（thtk 中可能是 RAND）。其他 ID 静默返回 0。
- 弹幕随机模式 6/8（`bullet_ops.go:343-388`）用 `tp.angle + (randFloat-0.5)*angleInc*ways`；原作
  （`round2/func_4067d0.c`）为 `rand01*X + a2`（X 可能是 a1-a2，反编译未完全还原）。原作 mode 8
  先抽角度后抽速度。`randSpeed`（`bullet_ops.go:392-398`）上下界颠倒。

## 6. 子弹

**原作每帧**（`round2/func_406240.c`），按子弹状态：

- 状态 2 出生：模板默认 flags 0x203，子弹通常从这里开始；出生时从发射点**后退 4 倍速度**
  （`func_4067d0.c`）；以半速移动、无判定，直到出生动画结束；结束那一帧切到状态 1 并立即执行
  状态 1 逻辑。
- 状态 1 活动：先跑变换链（`FUN_00406d90`），再 pos += vel × timescale，再做命中与擦弹。
- 状态 3：半速。
- 速度是缓存的 float32 向量（`FUN_00408750`），z = 0.1。
- 出屏（`FUN_00406160`）用精灵宽高，且只在 10 帧宽限计数（+0x434）耗尽后生效。

**项目**（`entity/bullet/bullet.go:87-114`）：actions → 速度/角度加速度 → float64 重算速度并移动
→ Age++ → 固定 64 px 边距出屏（激光 96+宽）。**没有出生状态**：满速出射、立即可命中、发射当帧就移动。

**etEx（409）**：原作参数 (slot, idx, async, type, a, b, r, s)；变换链**顺序执行**，最多 18 项，
从存储的索引开始；async==0 的项在仍有变换活动时等待；`a` 是**持续帧数**而不是延迟。

| type | 原作 | 项目 |
|---|---|---|
| 1 | 加速计时 | 缺 |
| 0x10 | 以角度 s 施加加速度 r，持续 a 帧 | SetAccel，永久 |
| 0x20 | 加速度 r + 角速度 s，持续 a 帧 | AngleAccel，永久 |
| 0x40/0x80/0x100 | 每隔 a 帧调整角度或速度，共 b 次 | 只有 64（SetMotion） |
| 0x400/0x800/0x8000000 | 墙壁反弹 | 缺 |
| 0x1000/0x1000000 | 计数器 | 缺 |
| 0x2000 | 出屏宽限 | 当作 Expire（错） |
| 0x4000 | 重设精灵 | 缺 |
| 0x8000 | 等待 | 缺 |
| 0x10000 | 删除 | 缺 |
| 0x20000 | 音效 | 缺 |
| 0x100000/0x200000 | 计时器 | 缺 |
| 0x400000 | 分裂出新一轮 | 缺 |
| 0x2000000 | 跳转到某项 | 缺 |

项目 `eclEx`（`bullet_ops.go:34-39`）/`applyETEx`（`:216-238`）读 [3] flags、[4] delay、[6] f1、[7] f2，
忽略 [2] async 和 [5]；`applyEx`（`:400-443`）/`applyActions`（`bullet.go:116-149`）把它们变成
Age >= Start 时的一次性动作。

**发射（401）**：`emit`（`bullet_ops.go:305-339`）用上次 integrate 的世界坐标（同帧 setPos 后已过时）；
缺原作的最小距离门限（+0x1454==0 或自机距离更远才发射，由 346 设置）。外层 stacks、内层 ways 的顺序正确。

**模板默认（400）**（`bullet_ops.go:56`）：项目 sprite 1、speed 2、ways/stacks 1；原作 sprite 0、
sound 7、flags 0x203。`eclTemplate`（`:17-32`）没有 flags 字段。

**弹种**：`mapBulletType`（`bullet_ops.go:522-539`）把 28 种精灵压成 4 种。

**激光**：只实现 412/413/428/431/433（`bullet_ops.go:445-512`）；431/433 还应复制 0 号模板的变换表。

**擦弹**（`bullet.go:162-179`）：每弹一次、半径×5，与原作一致；但项目额外要求 Age > 4（`stage.go:344`）。

**对象池**：线性扫描，容量 2048（原作 2000）。

## 8. 更新顺序与删除

项目 `Stage.Update`（`stage.go:225-278`）：对话冻结 → Frame++ → DecayFaith → updatePlayer →
script.Update（ECL VM）→ 敌人 → 子弹 → 道具/特效 → checkCollisions → cleanEnemies。

VM 内部（`vm.go:248-325`）先积分**所有**角色的运动（`:291-297`），再执行**所有**脚本（`:305-314`）。
原作按敌人逐个处理（`FUN_0040dc80`）：运动积分 → 取整 → 边界钳制 → 出屏判定 → 该敌人 ECL →
伤害与碰撞。项目中途新建的脚本要到下一 tick 才执行。

删除规则：原作敌人出屏用自身尺寸、对所有敌人生效，只在已进入过屏幕（0x100）且 0x4 未置位时删除；
项目固定半尺寸 16、只针对杂兵（`game_ops.go:76-104`），`cleanEnemies`（`stage.go:470-484`）还会删除
超出 64 px 的任何东西（包括 Boss），原作没有这条路径。`enemy.InBounds` 边距 64（`enemy.go:263`）。

原作管理器之间的顺序已确认：自机 → 敌人（含各自 ECL）→ 激光 → 子弹 → 道具，见 `m2_motion.md` §1。
