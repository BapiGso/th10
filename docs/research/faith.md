# 信仰：保持计时、衰减与补充

> 来源：`th10.exe` v1.00a 的 Ghidra 反编译与汇编（`.tmp/ecl_dump/faith/`）。
> 地址均为原作地址；“项目”指 `game/state.go` 等 Go 代码。

## 0. 存储与单位

信仰块的基址是 `DAT_00474c40`（`this` 的取值，`&DAT_00474c40`）。各字段：

| 偏移 | 全局 | 含义 | 来源 |
|---|---|---|---|
| +0x00 | 474c40 | 最高分 | FUN_00417870 |
| +0x04 | 474c44 | 得分（存储值，显示 ×10） | FUN_00409d90 |
| +0x0c | 474c4c | 信仰（存储值，等于显示值 / 10） | FUN_0041be80 |
| +0x10 | 474c50 | 衰减速率（每个衰减帧减去的存储值） | FUN_00417870、FUN_0040dc80、FUN_00418a00 |
| +0x14 | 474c54 | 保持计时的前一值（只写不读，不可观察） | FUN_0044bf40 |
| +0x18 | 474c58 | 保持计时（整数，帧） | FUN_00412ff0、FUN_00418a00 |
| +0x1c | 474c5c | 保持计时的浮点累加器 | FUN_0044bf40 |
| +0x20 | 474c60 | 速度指针，指向 `DAT_00476f78` | FUN_0042a6a0、FUN_00418b80 |
| +0x24 | 474c64 | bit0：速度指针已安装 | FUN_00418b80 |

信仰按 `FUN_0041be80`、`FUN_00412e70` 等的写法以“存储值”（显示值 / 10）计算，下限 5000、上限 99999
（存储值）。项目 `GameState.Faith` 保存存储值 ×10（下限 50000、上限 999990）。

## 1. 保持计时（+0x18）

**加**：`FUN_00412ff0(n)`（`0x412ff0`）。计时 < 0x82（130）时才加：调用 `FUN_0044bf40(n)`，
再把累加器取整写回计时；计时超过 130 时钳到 130（累加器置 130.0f，`0x43020000`）。计时已经是 130 时整个
函数什么也不做。

**减**：`FUN_00418a00`（`0x418a00`）在计时 > 0 时调用 `FUN_0044bf40(-1.0)`（`0x418a08`），每个门控开启的
帧减 1。

**FUN_0044bf40**（`0x44bf40`）：先把计时（+0x18）复制到前一值（+0x14），再取速度 `s = [+0x20]`：

- 若 `0.99 < s < 1.01`（`0x470b68` = 0.99f，`0x470b64` = 1.01f），累加器 `+= n`（快路径）；
- 否则 `acc += n · s`（慢路径）；
- 最后 `计时 = FUN_00463b2c(acc)`。`FUN_00463b2c`（`0x463b2c`）是截断到零的取整（与 C 的 `(int)` 相同）。

**速度恒为 1.0**：`DAT_00476f78` 的写入只有 `FUN_00417870`（`0x4178b1`）和 `FUN_00417c80`（`0x417ca9`），
都写 1.0f。因此只有快路径可达，累加器始终是整数，计时就是累加器的整数值。项目只实现快路径。

计时的取值范围是 0..130，门控开启时每帧减 1。

## 2. 衰减（FUN_00418a00，`0x418a00`）

计时 ≤ 0 时（门控开启的帧），若存储信仰 > 5000（`0x1388`）：

1. 存储信仰 −= 旧的 `+0x10`（先用旧值）；
2. 若旧速率 < 18（`0x12`），速率置 18；
3. 存储信仰钳到不低于 5000。

**速率 `DAT_00474c50` 的取值**（都是原作写入点）：

| 值 | 写入点 | 时机 |
|---|---|---|
| 9 | FUN_00417870 `0x417a00` | 每次关卡开始（无条件，所有分支） |
| 1 | FUN_0040dc80 `0x40e26b` | 每个敌机帧，只要它没有被删除（早退条件见本节下文），与是否受弹无关 |
| 18 | FUN_00418a00 `0x418a30` | 衰减步之后，速率至少为 18 |

结果：某帧有敌机执行到 `0x40e26b`，该帧的衰减量是 **1**（存储值，即显示 10）；否则是 **18**（显示 180）。
关卡开始后、没有敌机的第一次衰减是 9。敌机的击破（`FUN_0040e5f0` 返回非零）不设速率。

FUN_0040dc80 对每个敌机的调用来自 `FUN_0040d750`（`0x40d750`，遍历敌机表）和 `FUN_0040cfb0`（`0x40cfb0`，
创建时调用一次）。敌机帧的早退条件：`+0x2480 & 0x400`（本帧已执行）、`FUN_0044fd10` 非零（ECL 结束或删除，
返回 −1）、`(flags & 0x11) != 0`（不可被射击，如 ECL 0x1、0x10），这些情况下都不设速率。

## 3. 每帧门控（FUN_00418190，`0x418190`）

`FUN_00418a00` 只在 `FUN_00418190` 的末尾（`0x418764`）、`FUN_00404450`（calc chain，含敌机帧）、
`FUN_00417040`（HUD）之后被调用，且只有同时满足以下条件时才调用（`0x418751`..`0x418764`）：

- **无 Boss 在槽 0**：`DAT_00477704+0x10 == 0`。槽位由 ins_332 设置（`FUN_0040e770` `0x40fffe`），ins_332(-1) 清空（`0x40ffb7`）；敌机删除时由
  `FUN_0040dae0`（`0x40dae0`）清空。
- **无对话**：`DAT_0047770c+0x9eb8 == 0`（MSG 状态）。
- **关卡时钟 ≥ 90**：`+0x14 >= 0x5a`（`0x418759`..`0x41875d`）。
- 不在 `FUN_00418190` 的早退（`return 3`，`+0x58` 的 0x10/0x20/0x40）之后。

`FUN_00418190` 末尾随后才递增 `DAT_00474c88/8c`（关卡帧计数）。

## 4. 补充与消耗

**补充保持计时**（`FUN_00412ff0` 的调用点，`FUN_0041afd0` 的道具收集、`FUN_0040e5f0` 的击破）：

| 事件 | 调用点 | 保持计时 | 同时的信仰变化（存储值） |
|---|---|---|---|
| 敌机击破 | `FUN_0040e5f0` `0x40e681` | +10 | 无 |
| 道具 1/10（火力） | `FUN_0041afd0` `0x41b473`、`0x41b4a0` | +60（升级或否，都加） | 无 |
| 道具 2（得点） | `0x41b575`（`LAB_0041b559`） | +100 | 无 |
| 道具 3（大信仰） | `0x41b5cc` | +120 | `FUN_0041be80(n)`：+n/10，n = 5000/8000/10000（按难度） |
| 道具 4/11（大火力） | `0x41b6cc`、`0x41b6f6` | +20 | 无 |
| 道具 5（大得点） | `0x41b575`（`LAB_0041b559`） | +100 | 无 |
| 道具 7（残机） | — | 0 | 无 |
| 道具 8（消弹） | `0x41b5e9` | +3 | `FUN_0041be80(10)`：+1 |
| 道具 9（信仰） | `0x41b624` | +60 | `FUN_0041be80(100)`：+10 |

**不补充、不减计时的事件**：

- 死亡 `FUN_004269d0`（`0x4269d0`）：存储信仰超过 5000 的部分减去三分之一（不低于 5000）；不改计时与速率。
- 灵击 `FUN_00412e70(3000)`（`0x412e70`，调用点 `FUN_00425730` `0x425a1f`）：存储信仰 −300，下限 5000；
  不改计时与速率。
- ECL 槽中断 `FUN_004127a0`（`0x4127a0`）：存储信仰 −3000，下限 5000（`0x1388`）；不改计时与速率。

**关卡开始**（`FUN_00417870`，`0x417870`）：

- 速率 = 9（`0x417a00`，无条件）。
- 仅在 `DAT_00491fc4 != 0` 分支：`FUN_00418b80(&DAT_00474c40, 50000)`（`0x417941`），即信仰 = 5000（存储）、
  计时 = 0、累加器 = 0。该分支选择的含义未确认（见 §6）。

**回放章节**：

- 写入（`FUN_00428f60`）：章节头 +0x14 ← 存储信仰（读 `DAT_00474c4c` 于 `0x4290d3`），+0x18 ← 保持计时（读 `DAT_00474c58` 于 `0x4290dc`）。
- 读取（`FUN_0042a6a0`，`0x42a6a0`）：信仰经 `FUN_00418b80(·, +0x14 · 10)`；保持计时 ← 章节 +0x18（`0x42a7b9`），累加器 ←
  同值（`0x42a7c4`）；前一值 ← 计时 − 1（`0x42a7bf`，不可观察）。速率不在章节头里，不恢复。
- 验证数据（`th10_05.rpy`）：第 1 章（新开始）+0x18 = 0；第 2–6 章为 130、129、130、129、129。
  这与“被 130 钳住的计时”一致，不是帧计数。

## 5. 每帧的顺序（项目实现）

项目 `Stage.update` 的顺序对应原作（以 FUN_00418190 为准）：

1. 玩家、灵击、脚本、敌机（`vm.Update`，内含 FUN_0040dc80 的对应部分：`updateActor` 中 `FaithRate = 1`）；
2. 子弹、道具（拾取调用 `AddFaithHold`）、特效、ECL 后处理（击破调用 `AddFaithHold(10)`）；
3. 对话（`UpdateMSG`）；
4. 信仰保持与衰减：`faithGate()` 为真时 `TickFaith()`（FUN_00418a00）；
5. 清理敌机。

## 6. 未确定或未验证的部分

1. **关卡时钟 +0x14 的写入点未找到**。在 FUN_00418190 里只读不写；Ghidra 的写入搜索也没有找到。门控按
   “零基帧号 ≥ 90”（即项目的 `Frame > 90`）推断，依据是 FUN_00418190 的初始化分支只在 +0x14 == 0 时运行。
2. **`DAT_00491fc4` 的写入点未找到**（Ghidra 只有读取引用）。它决定关卡开始时是否执行 FUN_00418b80(50000)，
   即是否清零信仰与计时。项目维持现状（信仰跨关卡结转，计时不清零）。
3. **原作 trace 不能验证信仰**。`.tmp/trace/orig_05_s2..s6.txt` 是探针修正前采集的：信仰列每帧为 0、得分列恒为
   1000000。项目的信仰只能靠单元测试（按汇编规则）和前后对比验证。需要用现在的 `th10probe` 重新采集（需要用户运行原作；
   本次没有启动 th10.exe）。
4. **FUN_0044fd10 的对应关系**：项目 `updateActor` 的 `runActor` 返回 false 处对应 FUN_0040dc80 的 `return -1`，
   这是已有的移植，本次未逐条核对。
5. **慢路径不可达**：DAT_00476f78 恒为 1.0，项目只实现快路径（`AddFaithHold`、`TickFaith` 的注释有说明）。
