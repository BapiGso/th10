# 探针扩展、半帧与整段采集普查（t17）

日期：2026-11-08。对象：TH10 v1.00a，映像基址 `0x400000`，SHA-256 为 `2f14760b6fbbf57549541583283badb9a19a4222b90f0a146d5aa17f01dc9040`。

本普查先于工具实现。只读完整 `exe.asm`、已有 C／ASM、Go 移植、回放和 trace，不运行原作、探针或 Ghidra。下面的地址都是原作虚拟地址，不是 Go 内存布局。

## 1．主循环与完成信号

依据：`render/func_439390.{c,asm}`、`render/func_4391f0.{c,asm}`、`render2/func_449c00.c`、`render2/func_449d40.c`、`r11/func_417870.asm`，以及完整 `.tmp/ecl_dump/t4_native/exe.asm`。

`FUN_00438ad0` 的 `0x438d2c–0x438d31` 以 `0x4924f0` 为参数调用 `FUN_00439390`。一次有效更新的顺序是：

1．`FUN_00439540` 取高精度时间。主循环对象 `+0x38／+0x40` 写当前时间；未超过 `+0x48` 的 1／60 秒网格时 `Sleep(0)` 返回，不跑 calc。超过网格时先推进 `+0x48`。
2．设置二维矩阵、视口；`0x43942f` 调 `FUN_00449c00` 跑整条 calc 链。
3．`0x43943b` 刷新音效队列。calc 返回 0 或 −1 是退出分支，不进入绘制。
4．`0x439473–0x439478` 递增主循环 `+0x14` 的有符号字节（全局 `0x492504`）。达到 cfg `0x491d66 + 1` 才进入绘制。
5．`BeginScene`（设备 vtable `+0xa4`）→ `FUN_00449d40` 的整条 draw 链 → 批处理 flush → `SetTexture(0,0)` → `EndScene`（`+0xa8`）。
6．`0x439508` 把绘制计数清零；`FUN_004391f0` 的设备 vtable `+0x44` 才是 `Present`。驱动等待垂直同步发生在此处，而不是 calc 中。
7．`0x439511–0x43951b` 取结束时间，写 `double [0x4923a0] = 结束时间 - 本轮开始时间`，然后返回消息循环。

`FUN_00439890` 的 `D3DPRESENT_PARAMETERS` 是全屏首选 `Interval=ONE`、60 Hz；回退可能 `IMMEDIATE`；窗口为 `DEFAULT`。因此不能假定所有机器都有同样长的 Present 等待窗口。

### 1.1 不能当作完成标志的字段

- `DAT_00474c88` 是关卡实帧号，但 `FUN_00418190` 注册在 calc 优先级 `0x0a`（`0x417a22`），在 `0x418779` 递增；输入 `0x0b`、自机 `0x10`、敌机 `0x12`、激光 `0x13`、道具 `0x15`、MSG `0x18`、World `0x1a` 都还没跑完。其前后相等只能排除跨实帧，不能排除半帧。
- `DAT_00474c8c` 在同处递增，但 MSG／ECL 344 会清它；它是独立 section 时钟，不是第二个 calc 结束时钟。
- `DAT_00491fb0` 是绘制矩阵／模式状态，被多个 draw 节点写 0／1；不是 calc／draw 阶段旗标。
- `DAT_0049231c` 是链表 critical section 的嵌套字节；`0x449c67` 在调用每个 calc 回调前减它，回调结束才加。GDI 长停顿时它与空闲时同为 0，不能据此宣称采样稳定。
- 两次相同快照也不等于已经完成：MSG op 16 的 GDI 渲染可能在两次读取之间一直停着。

### 1.2 采用的只读完成依据与边界

探针使用以下主循环完成“见证”，再做两次逻辑快照与帧号／管理器身份的前后括读：

- cfg 跳帧为 0 时，同一关卡帧下观察到 `int8 [0x492504] > 0`，证明当前 calc 已返回。只在跳帧为 0 时使用该脉冲，避免把上一轮累积的跳帧字节当成本轮完成。
- 在已经观察到目标帧之后，同一主循环开始时间下 `double [0x4923a0]` 改变，证明该轮已经走到尾部。
- 在已经观察到目标帧之后，`double [0x492528]` 的开始时间改变而关卡身份／帧号仍相同，证明持有目标帧的那轮已经返回。无垂直同步时，节流空转会很快产生这个见证。

先以小块读取等待见证，等待也计入预算，不在 GDI 停顿期间反复复制整个弹池。随后连续两次快照，只比较会输出的逻辑字段（以及全部敌弹的逻辑摘要），不比较 draw 会修改的 ANM 内存。任何必需内存读取失败、前后帧号／对象身份改变、快照不一致都重读；超过时间或次数预算仍不能确认，输出带 `H` 行的半帧，而不是丢掉后假装完整验证。

只读外部采样不能取得原作主线程的锁，也不能补读已经释放的上一帧；见证之后下一次 calc 仍可能开始。括读与双快照是这一剩余竞态的防线，不是对任意线程停顿的数学原子快照承诺。探针不挂起线程、不调用 `GetThreadContext`、不注入结束计数器，也不改变游戏节拍。采样日志必须报告重读、半帧、漏采及用时，动态效果仍需用户提供新 trace。

## 4．旧 trace 截断原因

三份文件的静态尾部证据：

| 文件 | 字节数 | 模 4096 | 尾部 |
|---|---:|---:|---|
| `orig_th10_04.txt` | 55,783,424 | 0 | `B 72.812 33.664 ang -0.35903 spd 3.300`，缺 type／color／换行 |
| `orig_th10_02.txt` | 51,695,616 | 0 | `B 483.200 139.284 ang 2.64680 spd ` |
| `orig_th10_03_as_C.txt` | 29,384,704 | 0 | `B 25.` |

旧 `trace.NewWriter` 使用 4096 字节 `bufio.Writer`，F／M／E／B 各次 `Fprintf` 直接往这个缓冲写；只有 probe `run()` 的正常尾部显式 `Flush()`。进程读取失败直接 return 2，只 defer 了文件 Close，**Close 文件不会替 bufio 刷新**；Ctrl+C 默认结束进程同样不走 Flush。三个文件恰好停在 4096 边界、文字停在行中，与丢失未刷新的缓冲完全相符。具体是哪种退出方式没有现场日志，不能断言都是用户强杀。

修复方向：先序列化整个完整帧块，再以单次写提交；采集端每帧提交后刷新，不把帧的一半留在下次 Flush；对文件短写／写错误回滚到上一完整帧边界；所有正常／错误返回与可处理的中断都收尾刷新／关闭。扩展帧另有提交尾行，reader 能识别整行缺失的尾帧。强制 `TerminateProcess`、断电或底层存储故障不是任何 Go defer 能保证的；这类结果必须报告 INCOMPLETE，不能伪装 MATCH。

## 5．跨关与 demo 自动识别

### 5.1 跨关

- 当前场景 `0x491fb4`、请求 `0x491fb8`，i32；`FUN_00420470／004218d0／0040ac90` 写入。关内规范化为 7；跨关请求 11；回放最终请求 4。
- 关卡对象指针 `0x477810`，`+0x58` flags、`+0x5c` mode；`FUN_004180e0／00417870／00418190／00417c80`。加载 bit 4 期间不采正常世界。
- 回放管理器指针 `0x477838`，`+0x10` mode＝1，`+0x1d0` 当前**原关卡编号**；章节头指针在 `+0xb0 + stage*0x24`，读头 `u16 +0x00` 确认章节身份。输入计数在 `+0xb4 + stage*0x24`，由 `FUN_004297d0` 推进。
- `FUN_00415e90` 的 `0x416ede–0x416ee8` 在当前帧中请求 11 并递增全局当前关卡 `0x474c7c`。故**不能只按这个全局分文件**，否则最后一帧会错放到下一章。用回放活动章／头指针与关卡帧号路由，跨关归零只换输出文件，不结束进程。
- 本地 `-replay` 只提供预期章节／输入长度／文件名，不控制原作；正常采集起止取原作状态，不用模拟出的终止帧数停止原作采样。
- 回放 Game Over 在 `FUN_00425730` 的 `0x425c93–0x425c9a` 直接请求 4，不打开可写的保存／继续菜单；探针同样先提交这一帧，再关闭采集。原作已经退出而末计数未被采到时报告 INCOMPLETE，不把上一帧改名冒充最后一帧。

### 5.2 demo

`FUN_0042cdf0` 的 `0x42ce02–0x42cf31` 证实：标题页 1／2 待机 900 帧，置 `DAT_00474ca0 & 0x20`，从表 `0x476ff8` 取 `demo1／2／3／0` 的名字，复制到 `char[256] DAT_00477710`，然后请求场景 12。`DAT_00474ca8` 在加载后已经推进到下一项，**不能把该值直接当成正在播放的 demo 编号**。

探针可只读全局文件名 `DAT_00477710`，识别 `demo/demoN.rpy` 的 basename，并同时要求 Demo 位、活动回放 mode 1、关内场景和有效章头。这样无需按键、窗口消息或猜标题光标；到标题画面自动关文件，下一段按真实编号另开文件。重复同一个 demo 不覆盖已有采集，默认采齐四个不同编号后退出。

`FUN_00418190` 在零基关卡对象时钟 2940 发淡出，3000 请求 4；原作可能输出到实帧号 3001，需保留这帧而不是硬按 3000 截断探针。标题往返约每个 demo 65 秒，四个约 4～5 分钟，加载／慢机时间另加。

四个资源已经在 `assets/misc/demoN.rpy`，`gamedata.ReadFile("misc/demoN.rpy")` 可直接读嵌入字节，现有 `replay.Parse／ConfigFor／Stream` 能解码／回放。新 sim 的 `-demo N` 复用相同 headless 入口，在构造前置 Demo 位；默认只运行标题演示窗口，显式 `-frames 0` 可模拟资源的完整输入。正常 `-replay` 默认行为与六章 v2 输出保持不变。

## 6．开销与验收口径

旧探针稳定检查本就需要两次约 4.064 MB 弹池读取，并有 3 ms settle＋2 ms gap。扩展额外每快照 2.216 MB 道具池、最多约 0.29 MB 激光逻辑／模板前段，以及小块自机／资源／符卡；不复制激光 ANM、不逐槽发 2198 次系统调用。以本机只读复制有效吞吐 2～5 GB／s **估算**，新增双读约 0.9～2.5 ms；这是模型估算，不是实测原作数据。

完成见证等待只读几十字节；重试同时受总时间预算和快照次数上限约束，默认一帧 16.67 ms 内留出轮询／序列化余量。日志记录实际采样最大／平均耗时、跨帧与缺号数量，用户能核实是否增加漏采；不能在禁止运行 probe 的本任务中冒称实机性能已测。合成内存基准只测解码成本，不测 `ReadProcessMemory` 或原作速度。

整数精确比较；位置／长度／宽度／时钟浮点沿用既有 `eps + 0.001 + slack`，角度沿用 `ang-eps + 0.00001 + slack`，不扩大容差。半帧行自动跳过并单独计数，不计入匹配帧；旧 trace 没有 H／X，处理方式不变，仍用 `-after`（`-from-frame` 已于第五轮删除）。

## 7．实际接口与文件完整性

2026-11-08 实现结果：默认 v2 的 F／M／E／B 字节不变；`-ext` 才增加 X／S／I／L。采集入口或显式 sim 整段模式使用可选会话边界：

| 行 | 内容与校验 |
|---|---|
| C | 会话版本 1、文件章节索引、原关卡号、demo 编号（普通为 −1）、扩展版本、机体／难度、观测到的入场最高分／继续数字、输入长度、显式帧上限。无本地回放的探针只知道原章头声明长度，可能含重复保存倍数，不拿它当退出时钟。 |
| F／M／E／B | 原 v2 格式；正常默认 sim 不添加 C／Q／Z。 |
| H | 原因、重读次数、前后实帧号。没有完成见证时可以是零次快照的诊断行，未读到的数值不能作为验证样本。 |
| X | 扩展版本 1、最高分／HUD 分／信仰保持／rank／定点位置／时钟、实际道具与激光行数。 |
| S／I／L | 符卡保留字段；全部非空道具槽；全部链表激光（含待删除），都不复算。 |
| Z | 完整帧提交：帧号及 E／B／I／L／S 行数。只读诊断 H 可以包含部分逻辑数据，但提交的文本本身必须完整。 |
| Q | 已提交帧数、最后帧号、complete／interrupted／timeout／error／incomplete。缺 Q、缺 Z、丢整段末帧但留下错误 Q，或异常状态都报 INCOMPLETE。 |

`trace.NewAtomicWriter` 先在自身缓冲中完成整个帧，再单次 Write；文件短写／失败通过该文件句柄回滚到提交前偏移。采集每帧刷新外部用户态缓冲，结束时 Sync／Close；Ctrl+C、Ctrl+Break／可处理的终止信号和错误返回都走收尾。不会承诺强杀／断电时的持久性，也不向原作发送退出消息。输出文件用 O_EXCL 新建，不覆盖已有文件。

默认预算 10 ms、最多 4 次快照、settle 3 ms、相邻快照 gap 0.5 ms。相较旧 gap 2 ms 释放 1.5 ms；弹池／自机／道具的大缓冲复用，避免每帧重复分配 4～6 MB。合成内存基准单次扩展解码约 91.5 微秒（i7-12650H，热缓存），只证明解码路径成本，不是原作读取实测。

sim 可用 `-initial` 或 `-initial-dir` 从对应 C 读取入场最高分，构造 Go 状态前注入；没有 C 的旧 trace 必须明确用 `-hiscore`，不能推算出不存在的回放字段。`-scope ext` 比较全部扩展类别，也可单独选 stats／items／lasers／spell；motion 不受影响。`-scope all` 在双方有扩展时也比较它们。四个嵌入 demo 的默认 3001 帧窗口和显式六章模式均已静态／合成及 sim 验收；原作采集效果仍待用户。
