## 2. 浮点

`CreateDevice` 没有带 `D3DCREATE_FPU_PRESERVE`，所以 x87 精度控制是 24 位。

- 精度控制只影响 FADD/FSUB/FMUL/FDIV/FSQRT。它们的结果和 float32 单步运算逐位相同，因此 Go 侧
  每一步都用 float32 运算即可。乘加要包一层 `float32()`，防止编译器融合成 FMA。
- `fsin`/`fcos` 按扩展精度计算，`fild` 精确。`polar` 实际是 `float32(cos_ext(a) * r)`，
  Go 写成 `float32(math.Cos(float64(a)) * float64(r))`，误差在 L2 预算内。

## 4. 基础函数

- **`FUN_0044bc70` 角度归一化**：float32 运算，`while a > π: a -= 2π`，`while a < −π: a += 2π`，
  两个循环**共用** 0x21 次迭代上限。`FUN_00413170` 就是 `layer.angle = norm(a)`。
- **`FUN_0044bb90` RNG 有符号浮点**：状态 `DAT_004918b0`，计数 `DAT_004918b4 += 2`。
  返回 `float32(raw) * float32(2^-31) - 1`，全程 float32。项目原来的 float64 版本要改。
- **`FUN_00452ff0`** 是 CRT `floor`（double）。

### 取整 `FUN_0044c2a0`

ESI 指向一个"位置块"（dword 下标）：[0..2] 位置，[3..5] 增量或圆心，[7] 角度，[8] 半径，[10] 标志。

```
if 非绕圆:  pos += delta            (x, y, z)
else:       pos.xy = polar([7], [8]) + [3..4];  pos.z = [5]
x = float32(floor(float64(float32(x * 100)))) * 0.01f
y 同理（z 不取整）
```

### 缓动 `FUN_0044c350(t = a/b)`

令 `u = 2t`，`v = 2 − u`。

| mode | 值 |
|---|---|
| 1 / 2 / 3 | t² / t³ / t⁴ |
| 4 / 5 / 6 | 1−(1−t)² / 1−(1−t)³ / 1−(1−t)⁴ |
| 9 | u ≥ 1：(2 − v²)·0.5；否则 u²·0.5 |
| 10 | u < 1：u³·0.5；否则 (2 − v³)·0.5 |
| 11 | u < 1：u⁴·0.5；否则 (2 − v⁴)·0.5 |
| 12 | u ≥ 1：(u−1)²·0.5 + 0.5；否则 0.5 − (1−u)²·0.5 |
| 13 / 14 | 同 12，改为三次 / 四次方 |
| 15 | 0 |
| 16 | 1 |
| 其余（0、7、8……） | t |

### 插值器 `FUN_00412ac0`（2D）/ `FUN_00404610`（3D）

2D 布局（15 个 dword）：start[0..1]、end[2..3]、tan0[4..5]、tan1[6..7]、prev[8]、time[9]、ftime[10]、
speedPtr[11]（指向全局速度 `DAT_00476f78`）、flags[12]、duration[13]、mode[14]。
3D 布局（19 个 dword）：start[0..2]、end[3..5]、tan0[6..8]、tan1[9..11]、prev[0xc]、time[0xd]、
ftime[0xe]、speedPtr[0xf]、flags[0x10]、duration[0x11]、mode[0x12]。

每次调用（duration > 0 时）：

```
prev = time
if speed <= 0.99 || speed >= 1.01: ftime += speed; time = ftol(ftime)
else:                                time++; ftime += 1
if time >= duration:
    time = duration; prev = duration-1; ftime = duration; duration = 0
    return mode == 7 ? start : end        // mode 7 实际只累加 N-1 次
switch mode:
    7:  start += end;  return start                 // 匀速增量
    17: start += tan1; tan1 += end; return start    // 速度 + 加速度
    8:  t = ftime/dur
        h00=(1+2t)(t−1)²  h01=(3−2t)t²  h10=(1−t)²t  h11=(t−1)t²
        return h00·start + h01·end + h10·tan0 + h11·tan1
    其余: return (end − start)·ease(mode, ftime/dur) + start
```

计时器重置 `FUN_00412db0`（2D）/ `FUN_004050d0`（3D）：time = 0，ftime = 0，prev = −1；
首次使用时还会把 speedPtr 设为 `&DAT_00476f78` 并置 flag 位 1。

281/283 传入的切线是零向量，所以 mode 8 退化为 smoothstep `3t² − 2t³`。

## 6. 单个敌人每帧更新 `FUN_0040dc80`

1. 已置 0x400 → 返回 0；否则置 0x400，并把当前块复制到 prev。
2. 速度插值 A → `A.angle = norm(out0)`，`A.speed = out1`；绕圆插值 A → `A.radius`、`A.radiusVel`。B 同理。
3. 对每一层：
   - 位置插值 duration == 0 且非绕圆：`delta.xy = polar(angle, speed)`，`delta.z = 0`；
   - 位置插值 duration == 0 且绕圆：`radius += radiusVel`，`angle = norm(speed + angle)`；
   - 否则：`delta = posInterp.step() − pos`。
4. `round(A)`（反汇编确认 ESI = EBP+0x58）；若置 0x40000，`B.pos += DAT_00491e6c/70/74`；
   `round(B)`（EBX = EBP+0x84）；`final.delta = (B.pos + A.pos) − final.pos`；`round(final)`。
5. 移动边界（0x200）：`final.x` 钳到 `[lx − w·0.5, lx + w·0.5]`，y 同理；然后 `A.pos = final − B.pos`。
6. 出屏：`x + sw·0.5 < −192`、`x − sw·0.5 > 192`、`y + sh·0.5 < 0` 或 `y − sh·0.5 > 448` 时，
   若已置 0x100 且未置 0x4 → 返回 −1（删除）；在屏内则置 0x100。
7. 灵击时切换 ANM。
8. 执行该敌人的 ECL（`FUN_0044fd10`），返回非 0 → 返回 −1。
9. 伤害（flags & 0x11 == 0 时）：
   - `FUN_00428630` 取伤害；自机 +0x458 ∈ {0, 2} 时除以 5；符卡中的 Boss 再除以 5，最少 1。
   - 未置 0x8 且无敌计时 < 1 时 HP −= 伤害。
   - 中断检查 `FUN_004127a0`，命中则重新执行 ECL。
   - HP < 1 且未置 0x40：`FUN_00409d90`（得分）、`FUN_0040e5f0`（死亡）。
   - 置 0x2000；`_DAT_00474c50 = 1`。
10. 再次中断检查 `FUN_004127a0`，命中则 `FUN_00450470` 替换子程序。
11. 与自机碰撞 `FUN_004266b0`（flags & 0x12 == 0 且 [0x50d] < 1）。
12. 方向动画（0x1000）：按最终增量 x，阈值 ±0.1。
13. 同步 8 个 ANM 槽。
14. 自机诱导目标（+0x3504）。
15. 闪烁、无敌、无碰撞计时器递减。
16. 敌人计时器推进。

管理器 `FUN_0040d750` 遍历链表：未置 0x20000 且 `FUN_0040dc80` 返回 0 → 清 0x400；
否则通过 vtable +0x14 删除。之后推进管理器自身的计时器（+0x40..+0x4c）。

**`next` 在调用 `FUN_0040dc80` 之前取出**，而 0x400 只在这里被清除（`FUN_0040dc80` 见到 0x400
提前返回 0 也算）。由此产生一个必须照搬的时序：

- 非尾部敌人在本帧创建的新敌人（追加在尾部）会在本帧稍后被遍历到：这次遍历什么都不做，只清 0x400。
- **尾部敌人创建的新敌人不会在本帧被遍历**，0x400 保留到下一帧；下一帧遍历时 `FUN_0040dc80`
  直接返回，于是这个敌人**整整少更新一帧**（运动和 ECL 都不跑），然后才清 0x400。
- 链表只有一个敌人时（例如关卡开头只有 main），它就是尾部，它创建的敌人都会少更新一帧。

### 关卡 main 也是敌人

`FUN_00418190`（关卡初始化）调用 `FUN_0040cfb0(DAT_00477704, "main" @0x46d278)`，16 个参数全 0。
所以 main 子程序跑在一个普通敌人上，与其他敌人走同一套 `FUN_0040dc80`（运动、出屏、ECL）。
stage01 的 main 以 `var(12); ins_322(16)` 开头，即置 0x10（无判定、不受伤），也不绘制。
main 是第一个被创建的敌人，但**不一定在链表头部**：它首帧（创建时）新建的敌人先入链表（见下一节），
例如 stage05 的 `MapleEnemy` 排在 main 前面。复刻里 main 与其他敌人共用 `vm.order`，不单独执行。

### 创建 `FUN_0040cfb0`

- 设置 A.pos = (x, y, z)、分数、道具、HP；flip 0x800 = in[6]；0x40000 = in[7]；
  变量从父敌人 +0xfc 复制；无敌计时器 = 2。
- **创建时立即调用 `FUN_0040dc80`**（第 49 行），它会置 0x400。所以新敌人在创建当帧完整更新一次
  （运动 + ECL）；之后是否在本帧被管理器再遍历，见上一节。
- **入链表在首次更新之后**（第 87–99 行追加到尾部，+0x60 计数 +1）。所以新敌人首次更新时再创建的
  敌人排在它前面。复刻：`createOp` 先注册 actor、`updateActor`，再追加到 `vm.order` 和 `ctx.Enemies`。
- 创建指令：0x100 = 256（相对父敌人**最终**位置 +0x2c）、0x101 绝对、0x104 = 260 相对 + flip、
  0x105 绝对 + flip；0x109–0x10c 是 Boss 条件变体；0x10e/0x10f = 270/271。参数为 (name, x, y, hp, score, item)。
  270/271 和 3D 父敌人下的 256 另有相机相关的处理，见 §12。

## 10. 差分闭环约定

- trace 坐标统一用原作的游戏坐标（场地顶部中点为原点，向右为 x、向下为 y）。复刻的屏幕坐标减去
  `(FieldLeft+192, FieldTop)` 即得。
- 敌人行按管理器链表顺序输出，包括隐藏的 main；复刻用 `ctx.ManagerOrder`（由 VM 设置）。
- 子弹行按池槽位顺序输出；两边的分配规则相同（§9），所以顺序可比。
- `th10probe`：等到关卡帧计时器 `DAT_00474c88` 归零或首次跳动才开始；每帧在计时器变化后等待
  `-settle-us`（默认 3 ms）再采样，采样后计时器若已变化就丢弃这一帧（避免读到半帧状态）；
  trace 的帧号就是计时器的值，漏采的帧在 `th10diff` 里跳过。
- `th10diff -scope motion` 只比较自机、敌人、子弹的位置、角度、速度、HP 和数量，不比分数、信仰、
  道具等 M2 尚未移植的数值；`-shift n` 用来对齐两边帧号的起点（待第一次实测后确定）。
- th10sim 用回放章节头里的关卡号（+0x00）、种子（+0x02）和 rank（+0x20）；全局头里的关卡号是
  通关进度（th10_05 是 8）。
- **th10_05 一面的可比范围目前只到约第 4777 帧**：之后是 Boss 战前对话，复刻在对话期间冻结整个
  世界并等待 Z，而这个回放从不按 Z。原作对话期间游戏照常运行，按 MSG 脚本的超时推进（M5）。

## 12. STD 相机与 3D 敌人（2026-10-31，四面差分）

四面道中的敌人由 270（`createOp` 的 0x10e，置 0x40000）在 3D 空间创建，位置跟着 STD 相机走。相机属于 STD 脚本，
所以复刻必须先跑 STD 的相机部分（`std/`），否则四面从第 32 帧起就对不上。

- **相机块**：位于 stage 对象 +0x2a4c，共 0x46 dword。每帧复制到相机槽 0，即 `DAT_00491d7c`（= 0x491c28 + 0x154）。

  | 偏移 | 内容 |
  |---|---|
  | +0 | 位置 |
  | +0xc | 朝向 |
  | +0x18 | up |
  | +0x3c | 眼点偏移（只有 STD op 12 写，TH10 的 .std 都不用） |
  | +0x48 | FOV |
  | +0xcc | 视口 (32, 16, 384, 448, 0, 1) |
  | +0xf0 | 本帧位移（`DAT_00491e6c..74`） |
  | +0xfc/+0x100 | 雾近/远 |
  | +0x114 | 雾颜色 |

  初值由构造函数 `FUN_00402230` 设置：位置 (0, 0, −600)，朝向 (0, 300, 600)，up (0, 1, 0)，FOV 取 `FUN_004216f0` 的默认值 0x3f060a92。
- **脚本 VM `FUN_00403c80`**，由 `FUN_00402720` 每帧调用，排在敌人管理器之前：
  - calc 先把位移清零；
  - 计时器在 +0x38，指令格式为 {u32 time, u16 op, u16 size, args}，`time ≤ 当前帧` 的指令依次执行；
  - op 0 停表，op 1 跳转，偏移相对脚本开头，同时设置计时器；
  - op 2 立即设位置，**位移 = 新 − 旧**；
  - op 3/5 是位置/朝向的定时插值（`zun.Interp`）；op 10/11 是 Hermite 插值（mode 8）；
  - op 4/6/7/8 分别设朝向、up、FOV、雾；op 9（定时雾）和 op 14（ANM 中断）只影响绘制，留待 M4；
  - 主循环之后计时器 +1，再依次步进朝向、位置插值。
  - 移植为 `std.VM`，测试 `std/vm_test.go`。
- **270**（case 0x10e）：创建位置的 x、y 加上相机位置的 x、y，z 不加。271 是 270 的变体，只在 0 号 Boss 槽为空时创建。
- **每帧运动**（`FUN_0040dc80`）：0x40000 敌人在 A 层 `FUN_0044c2a0` 之后、B 层 `FUN_0044c2a0` 之前执行 `B.pos += 相机位移`（`motion.step` 的 `cam` 参数）。
- **3D 父敌人下的 256**（case 0x100，以及转成 256 的 265）：
  1. 取 p = (arg.x + 父.final.x, arg.y + 父.final.y, 父.final.z)；
  2. `FUN_00401d20`（EBX = 0，ESI = 0x491c28）经 `FUN_004215a0` 重建视图矩阵和投影矩阵：
     视图 = LookAtLH(眼 = 位置 + 眼点偏移，目标 = 位置 + 朝向，up)，投影 = PerspectiveFovLH(fov, 384/448, 30, 1800)；
  3. 用单位世界矩阵（`DAT_00474df0`）做 `D3DXVec3Project`；
  4. 结果减去 (224, 16)（`DAT_00470b4c`/`DAT_00470b48`），换到 ECL 坐标，z = 0。
  - 只有 256 做这种投影，260（case 0x104）不做。
  - 移植为 `std.Camera.Project`。D3DX 内部的运算顺序按 Wine 实现，原版 d3dx9 实际走哪条代码路径没有追踪；四面全章一致，暂时可以认为两者等价。
- 296/297（case 0x128/0x129）只把 xyz 加到 A/B 层的位置，不重算最终位置。
