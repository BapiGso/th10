# 自机还原真值与当前边界

已还原取证的移动、Power 资源规则、决死窗口，以及灵梦 A 的 SHT 射击/诱导/副机布局。**其他五机体射击、完整 ANM 与灵击演出尚未还原，也未完成与原作动态内存的逐帧差分**。

## 来源与单位

原作 EXE：`.tmp/[th10]/th10.exe`，487936 bytes，SHA-256：

```
2f14760b6fbbf57549541583283badb9a19a4222b90f0a146d5aa17f01dc9040
```

Ghidra 缓存工程报告同一 SHA-256。反编译只读运行，未修改原作进程。
原作说明书：`.tmp/[th10]/附带文档/说明书（日文版）/html/`，CP932 编码。

**原作 `0x474c48` 是 16 位 Power，单位为显示值的 0.05，范围 0..100。**
项目继续用显示值的百分之一，范围 0..500，因此 `项目 Power = 原作 raw Power * 5`。
不能把反编译中的整数不经换算直接搬进项目。

## SHT 移动参数

六份官方资源放入 `assets/sht/`，从本地已有原作提取目录复制，哈希由 `sht/movement_test.go` 锁定。

- 头部 `u16@0` 为 3；`u16@2` 是射击组数（灵梦 A 已执行射击组，其他机体仍只读取移动参数）。
- `f32@0x10`：高速；`f32@0x14`：低速。
- `FUN_00426520` 重算 `0x18/0x1c` 的斜向速度。
- `0x4248dc..0x424926` 将四项速度乘 `100.0f`（`0x470b44`）后经 `FUN_00463b2c` 截断，保存至 player+`0x3d4..0x3e0`。
- `FUN_004250b0` 使用整数坐标，之后乘 `0.01f` 转为绘制位置。项目按 0.01 网格累计，尚未复制 x87/float32 每一步舍入。

| 角色 | 高速 | 低速 | 高速斜向每轴步长 | 低速斜向每轴步长 |
|---|---:|---:|---:|---:|
| 灵梦 A/B/C | 4.50 | 2.00 | 3.18 | 1.41 |
| 魔理沙 A/B/C | 5.00 | 2.00 | 3.53 | 1.41 |

`sht.ParseMovement` 仅解析必要的移动头部，不把未知的 SHT 碰撞/回收字段当作已知规则。
特别是 `FUN_004247f0` 会用 EXE 中的角色表覆盖 SHT 的部分字段，因此不能直接把 SHT 的前三个 float 全当成当前判定半径。

## 灵梦 A 射击（SHT + 原作回调）

`pl00a.sht` 的 10 组记录已由 `sht.Parse` 解码并运行。Power 档位为 `min(Power/100,4)`，低速组加 5；4.00 和 5.00 都是四副机。其他五机体仍使用旧射击逻辑。

### 记录格式与发弹

`FUN_00426520`：组表在 `0x110`，每组索引 8 bytes；记录长 `0x34`，首字节为负时结束。

| 偏移 | 字段 |
|---|---|
| 0 / 1 | 有符号字节周期 / 相位 |
| 2 | i16 伤害 |
| 4 / 8 | f32 发射相对位置 X/Y |
| 0xc / 0x10 | f32 判定宽/高 |
| 0x14 / 0x18 | f32 角度/速度 |
| 0x1c / 0x1d | 来源（0=自机、1..4=副机）/行为种类 |
| 0x1e / 0x20 | i16 飞行/命中 ANM 索引，运行时加 5 |
| 0x22 | i16 音效（-1 不播） |
| 0x24..0x30 | 四个回调索引 |

- `FUN_004281d0`：初次按 Z 从时钟 0 开始；一段按 0..15 运行，松键也打完本段。15 帧处持键则减 15，下一 tick 从 0 开始（不是简单取模的恒定 3 帧射击）。
- `FUN_00428160`：时钟 `% interval == phase` 时发射。
- 主弹：每组两发，偏移 X ±10、Y -8，速度 24，判定 18×48，周期 3；0..4 档每发伤害分别 15/14/13/11/12。
- 副机弹：每副机一发，速度 12，判定 16×16，周期 5；伤害依组表为 6 或 7。
- `FUN_00427e90`：出生坐标先减初速度，随后同 tick 运行更新；不能再额外多走一步。原作槽位 128，灵梦 A 已改为 128 槽。
- `FUN_00428630`：碰撞读取 SHT 尺寸/伤害；非激光击中后退出伤害态。当前立即回收，原作命中 ANM 的后续生命周期尚未保留。

### 诱导规则

`0x47476c` 初始化表 index 1 → `0x428ad0`，`0x474778` 更新表 index 1 → `0x428b10`。

- 出生复制自机当前目标，目标原作坐标 `abs(X)>224` 则不绑定。
- 目标标志含 `0x11` 或 `0xc0000` 则解除绑定；目标销毁后也解除。**在飞行中的旧子弹不重新选敌**。
- 未满 120 tick：按 `0x428ce0` 的最短角差，每 tick 修正差值的 0.2。
- 偏差 ≥π/4：速度 -0.3，下限 4；偏差 ≤π/12：+0.1，上限 16；中间区间不改速度。
- 无目标：+0.1，上限 16。
- 仍有目标且 age≥120：不再转向，速度每 tick +0.2（原代码这一分支没有 16 上限）。
- 以上常量从 PE 的 `0x470b48/4c`、`0x470c18/38/3c/40/44/48` 直接读取；Ghidra 遗漏的 x87 中间速度值以反汇编核对。

目标选择桥接使用当前 Stage 敌人顺序的首个合格对象并保持绑定。原作 `FUN_0040dc80` 有目标锁存与敌人调度顺序，当前尚未逐帧对齐整体调度，不能宣称所有场景都选中同一敌人。Stage 清理出界敌人时标为 inactive，以免诱导持续追踪已经移除的对象。

### 副机与显示

- 原作布局：SHT `0x20`（高速）和 `0x98`（低速），每模式 10 个 XYZ；索引表 `0x476f7c` 为 `[0,0,1,3,6]`，按 1..4 副机分组。
- `FUN_00426f70` 变更数量时初始化位置；`FUN_004250b0` 使用每轴 `(目标-当前)*30/100` 的整数插值，两轴都截断为 0 时吸附到目标。已实现。
- `assets/anm/pl00.anm` 已嵌入（SHA256 `600ae57cb0c538d0d7677d7979d25b4aaf554da5ff41de83cb00ed2a8acb303e`）。发弹使用脚本 5/7 的图片、旋转角与 alpha 128；副机使用脚本 17 的图片。不是完整 ANM VM，混合/入场缩放/中断/命中特效仍待接入。
- 已实际启动复刻窗口，输入长按 Z、Shift、右移，检查两张截图确认持续射击、诱导转向、四副机与低速收束。截图保存在 `.tmp/reimu-shots-{unfocused,focused}.png`，不是原作视觉差分。

## 尚未还原，禁止据此宣称帧精确

- 其他五机体射击仍是旧实现；`ValidateReimuA` 明确拒绝未知回调，避免将激光/爆破默认为直线弹。
- 射击音效虽已解码但尚未接入；命中后的 ANM 存活期、精确出屏尺寸/混合仍有差异。现有子弹在死亡/起爆首帧继续推进，但完整自机状态与原作顺序仍需差分。
- 灵击仍用旧的 300 帧占位生命周期、全屏清弹/白闪/伤害。`FUN_00405750` 表明其结束由 ANM 对象消失驱动，移动速度还区分角色；应将 ANM 生命周期、范围、伤害和结束无敌一起还原，不能随便改成另一个固定时长。
- 普通/决死起爆首帧仍沿用简化 Player 状态机；完整输入、碰撞、Timer 更新顺序未与原作逐帧比对。
- 死亡之后仍立即移动到复活位置；原作死亡演出、掉落延时（死亡 state 2 timer=3）、入场移动与无敌计时未完整接入。
- 道具运动、自动回收、满火力换信仰道具、其他 ECL 道具 ID、掉落顺序仍需校准。
- Faith 的增减、普通点符、灵击信仰惩罚等仍是旧近似；大得点只修正了“不再作为 Bomb 库存”及不重复乘倍率，不能据此宣称整个计分正确。
- 测试采用固定输入快照验证确定性与取证数值，不是原作动态内存的 golden trace。本轮未启动原作采集。
